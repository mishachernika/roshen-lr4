# Лабораторні роботи № 4–5 — Магазин «Рошен»

Варіант 13. студент: Чернік Михайло, група ІПЗ-41.

## Функціональність

- `calc_discount(total, is_member)` — сума до сплати зі знижкою за обсягом
  (0 % до 500 грн, 5 % від 500 до 1000 грн, 10 % понад 1000 грн) та знижкою
  за карткою постійного клієнта +3 %.
- `process_order(order, stock, prices, is_member)` — валідація замовлення
  (товар у прайс-листі, кількість додатна й не більша за залишок),
  розрахунок суми зі знижкою та списання товару зі складу; повертає `None`,
  якщо замовлення відхилено (склад при відмові не змінюється).

## Склад репозиторію

```
roshen_shop.py              прототип обробки замовлень і розрахунку знижки
metrics.py                  підрахунок метрик Холстеда та Спен
tests/test_shop.py          модульні тести прототипу (пакет T1: 8 тестів, ЛР4)
tests/test_system_blackbox.py  системні чорноящикові тести (пакет T2: ST-01…14, ЛР5)
tests/test_scenarios.py     інтеграційні сценарні тести (пакет T3: IT-01…04, ЛР5)
lab4_report.docx            звіт до лабораторної роботи № 4
ЛР5_Чернік.docx             звіт до лабораторної роботи № 5 (тестування та відлагодження)
```

## Запуск

```bash
python3 roshen_shop.py        # демонстраційний сценарій: «До сплати: 680.8»
python3 metrics.py            # метрики Холстеда та Спен
```

У Windows замість `python3` використовуйте `python`.

## Тестування

Всі три пакети виконуються однією командою з кореня проєкту:

```bash
python3 -m unittest discover -s tests -v
```

| Пакет | Рівень | Підхід | Тестів |
|-------|--------|--------|--------|
| T1 (`test_shop.py`) | модульне | білий ящик, ЛР4 | 8 |
| T2 (`test_system_blackbox.py`) | системне функціональне | чорний ящик: еквівалентне розбиття, граничні значення | 14 |
| T3 (`test_scenarios.py`) | інтеграційне сценарне | сірий ящик: наскрізні сценарії | 4 |

Разом 26 тестів; покриття коду з обліком гілок — 96 %:

```bash
python -m pip install coverage
python -m coverage run --branch -m unittest discover -s tests
python -m coverage report -m
```

Тести ST-12 та ST-13 — відтворювачі дефектів D-01 (від'ємна кількість товару
приймалася, залишок зростав) і D-02 (нульова кількість приймалася як коректне
замовлення), знайдених у ЛР5 та виправлених валідацією кількості в
`process_order` (вимога R-05); вони залишено в комплекті як регресійні.
